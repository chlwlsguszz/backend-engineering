# Market Engine | 1,000만 상품을 검색하고 주문하는 커머스 백엔드

**백엔드 개인 프로젝트**　 Java 21, Spring Boot, PostgreSQL, Elasticsearch, Redis, k6

검색 결과에서 고른 상품을 그대로 주문할 수 있도록, 색상별로 재고를 가진 1,000만 개의 상품을 만들었습니다. 가장 신경 쓴 건 마지막 한 개를 산 고객이 응답을 못 받고 구매 버튼을 다시 눌렀을 때였습니다.

## 구매 버튼을 두 번 눌러도 주문은 한 건

**3회 → 1회**　신규 주문 한 건당 DB 커넥션 대여

마지막 재고 한 개로 재시도를 시험해 보니, 첫 주문은 성공했는데 두 번째 요청에는 품절이 떴습니다. 브라우저가 재시도할 때 같은 주문 키를 보내고, 서버는 이미 접수한 주문을 찾아 같은 번호를 돌려주도록 고쳤습니다. 회원 조회와 재고 차감도 한 트랜잭션에 묶었습니다. 중복 10건을 포함해 60번 주문했을 때, 주문 50건이 남았고 재고도 50개 줄었습니다.

## 검색 엔진이 멈춘 사이에 들어온 주문

**10 → 7 → 10개**　장애 복구 실험에서 확인한 재고

주문과 재고를 저장할 때 검색에 반영할 변경도 같은 트랜잭션에 남겼습니다. 워커가 이 기록(Outbox)을 읽어 Elasticsearch를 갱신하므로 주문은 검색 엔진의 응답을 기다릴 필요가 없습니다. 재고가 10개일 때 검색 엔진을 끄고 2개를 주문한 뒤 수량을 3개로 바꿨습니다. 복구 후 검색 재고는 7개, 같은 주문을 두 번 취소한 뒤에는 10개였습니다.

## 1,000만 건을 다시 색인하는 시간

**약 5분 15초**　1,000만 건 전체 재색인

기존에는 상품 5,000개를 검색 엔진에 다 써야 다음 배치를 읽을 수 있었습니다. 이제 DB에서 다음 배치를 읽는 동안 워커가 앞 배치를 색인합니다. 검색 엔진이 밀리면 읽기도 잠시 멈추도록 했습니다. 워커 8개, 배치 5,000건으로 측정했습니다. 적재를 마친 뒤 원본 상품 수와 검색 문서 수가 일치했습니다.
